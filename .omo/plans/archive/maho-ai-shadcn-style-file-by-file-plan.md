# Maho AI Panel — shadcn-Style Architecture Migration: File-by-File Plan

## Title & Companion Plan

This plan is the file-level execution layout for the migration described in the parent design plan, [`maho-ai-dia-complete-implementation-plan.md`](./maho-ai-dia-complete-implementation-plan.md). Read that first for design intent and acceptance criteria. This document only enumerates the concrete file changes required, broken into implementation waves.

## Scope

- **Target surface:** `maho-chromium/browser/resources/maho_ai/` (the AI side-panel WebUI).
- **Goal:** rebuild the React UI in a *shadcn-style* architecture (composable primitives in a `ui/` folder, `cva` variants, `forwardRef` + `asChild` slot pattern, single `cn()` helper) **without adopting Tailwind**. CSS continues to be hand-authored against the existing `--maho-ai-*` design tokens.
- **Reuses, not rewrites:** `maho_common/react/primitives/`, the Mojo bridge, `store.ts`, `types.ts`, `views/cards.ts` markdown renderer, and the opencode backend behind it.
- **Out of scope:** any Mojo IDL change, any opencode/transport/host change, any Tailwind adoption, any change to `mail/`, `website/`, `maho/crates/`, or upstream Chromium overrides.

## Assumptions

1. The website workspace already provides `class-variance-authority`, `tailwind-merge`, `lucide-react`, `@radix-ui/react-*`, and React 19. The bundler in `bundle_react.mjs` resolves through `website/node_modules/` and is guarded by `bundle_guard.mjs`. Adding the small set of packages below requires no new install action — they are already present in `website/package.json`.
2. We are explicitly **not** pulling Tailwind: `tailwind-merge`'s `twMerge` will still be used inside `cn()` because it is a pure string deduplicator and is harmless against non-Tailwind class names. If review prefers to drop the dep, `cn()` can fall back to `clsx`-only behavior.
3. `chrome://maho-ai/sf-symbol/` URLs remain the icon source. `lucide-react` is permitted only for non-brand chrome icons where it improves polish; SF Symbol bridge stays primary so the visual system is preserved.
4. CSS classes generated by variant primitives use the existing `--maho-ai-*` tokens; no new color palette is introduced. Shadcn's class-name convention is mapped onto Maho's existing BEM-ish names (e.g., `compact-thread__bubble--plain`) by keeping those classes as variant outputs of the relevant primitive.
5. The compact-vs-developer split, the overflow menu behavior, the approval flow, and the Mojo store binding all remain functionally identical. This migration is structural, not behavioral.
6. Verification gates use the canonical lock-backed build: `python3 maho-chromium/build/scripts/build_maho.py`. No raw ninja invocation. Smaller checks use `cd maho && bun run typecheck`.

## Architectural Translation: shadcn → Maho

| shadcn convention | Maho-shadcn-style equivalent |
|---|---|
| `components/ui/button.tsx` w/ `cva` variants | `react/ui/button.tsx` exporting `Button` + `buttonVariants` returning Maho CSS class names (`compact-icon-button`, `console-button--primary`, etc.) |
| Tailwind utility classes inside variants | Hand-mapped Maho BEM class names from `maho_ai.css` |
| `cn()` = `clsx` + `twMerge` | `react/lib/cn.ts` — same signature; safe on non-Tailwind classes |
| `asChild` via `@radix-ui/react-slot` | Same; we already pull Radix |
| Headless behavior via Radix | Same; `Dialog`, `Popover`, `Tooltip`, `DropdownMenu` Radix primitives |
| One file per primitive | Same; `react/ui/{primitive}.tsx` |
| Feature-scoped composition | `react/features/{feature}/*` for domain components composing primitives |
| `lib/utils.ts` | `react/lib/{cn,format,timestamp}.ts` |

The final React tree is composed of Maho features composing Maho-shadcn primitives that emit Maho CSS class names. Tailwind never enters the loop.

### `maho-chromium/browser/resources/maho_ai/BUILD.gn` — **Edit**

- **Planned changes:**
  - Expand `inputs` for the `bundle_react` action to include every new file under `react/lib/`, `react/ui/`, `react/features/`, `react/hooks/`, and the new `styles/*.css` files.

## Sequencing — Implementation Waves

Each wave ends with a hard verification gate. No wave proceeds without the gate passing.

### Wave 0 — Plumbing (zero behavioral change)

1. Create `react/lib/cn.ts`, `react/lib/format-timestamp.ts`, `react/lib/editable-snapshot.ts`, `react/hooks/use-app-state.ts`, `react/hooks/use-auto-scroll.ts`.

3. Update `BUILD.gn` `inputs` for the new files.
4. **Gate:** `python3 maho-chromium/build/scripts/build_maho.py` succeeds; `chrome://maho-ai` looks identical to main.

### Wave 1 — Button + Textarea + DropdownMenu primitives

5. Create `react/ui/button.tsx` with the full variant set. Replace inline buttons in `app.tsx` one-at-a-time, starting with the leaf-most (approval buttons, send button, icon buttons), commiting per replacement.

12. **Gate:** build green; smoke per Wave 1; bundle size delta inspected.
